## 4. 핵심 메트릭 수집법

### 4.1. N (후보 풀 크기)
- **정의:** `search_k = RETRIEVER_CONFIG["search_kwargs"]["k"]` (기본 25)
- **수집:** `config.yml` 라인 84 직접 읽기
- **로그 확인:** `[RAG] [RETRIEVE]` 내 `search_k` 값

### 4.2. S (하이브리드 가중치)
- **정의:** `ensemble_weights = [0.4, 0.6]` (BM25:FAISS)
- **수집:** `config.yml` 라인 86
- **로그 확인:** `[RAG] [RETRIEVE] 하이브리드 가중치 적용: bm25(0.40), faiss(0.60)`

### 4.3. r (재랭킹 Top-K)
- **정의:** `rerank_top_k = min(GRADING_CONFIG["top_k"], len(final_docs))` (기본 5)
- **수집:** `config.yml` 라인 258
- **로그 확인:** `[RAG] [RETRIEVE] 리랭킹 선별 완료: N개 후보 중 M개 최종 선별`

### 4.4. t_embed (임베딩 시간)
- **정의:** `_get_embeddings()` 및 `_get_doc_embeddings()` 내부 처리 시간
- **수집 방법:**
  1. **캐시 히트 시:** `t_embed ≈ 0ms` (캐시에서 직접 반환)
  2. **캐시 미스 시:** Ollama `/api/embed` HTTP 왕복 시간 + 배치 처리 시간
  3. **측정 포인트:** `src/core/semantic_chunker.py:310-453` `_get_embeddings()` 진입/이탈
  4. **캐시 키:** `emb:{model_name}:{xxhash.xxh64(norm_text.encode()).hexdigest()}`
- **로그:** `[Chunker] {len(missing_texts)}개 문장 신규 임베딩 생성 중`

### 4.5. search_ms (검색 시간 분리)
- **BM25 vs FAISS 분리:**
  - `src/core/graph/_retrieval.py:223-230`에서 `asyncio.create_task`로 병렬 실행
  - `search_tasks["bm25"]` / `search_tasks["faiss"]` 각각의 task 완료 시점
  - **분리 측정:** `search_bm25_with_scores()`와 `search_faiss_with_scores()`를 각각 래핑하여 개별 `time.perf_counter()` 측정
- **로그:** `[RAG] [RETRIEVE][TIMING] search_ms=...` (합산값)
- **개별 분리 명령:**
  ```python
  # 벤치마크 스크립트 내에서 개별 측정 예시
  t0_bm25 = time.perf_counter()
  bm25_results = await search_bm25_with_scores(bm25_retriever, query, search_k)
  bm25_ms = (time.perf_counter() - t0_bm25) * 1000

  t0_faiss = time.perf_counter()
  faiss_results = await search_faiss_with_scores(faiss_retriever, query, search_k)
  faiss_ms = (time.perf_counter() - t0_faiss) * 1000
  ```

### 4.6. T_llm (LLM 생성 시간)
- **정의:** `generate` 노드 내 LLM 추론 시간
- **수집:** `eval_quality.py` 내 `TTFT = t_first - t_start`, `TPS = eval_count / (t_end - t_first)`
- **로그:** `[RAG] [RETRIEVE][TIMING]` 에 `total_ms` 포함
- **단축 경로:** `is_cached=True` 시 `T_llm ≈ 0ms` (쿼리 캐시 히트)

### 4.7. Short-circuit %
- **정의:** LLM grade를 생략한 쿼리 비율
- **조건 1:** `len(query) < 6` → 재랭킹 생략, `rerank_engine="rrf"` (라인 340-347)
- **조건 2:** `max_rerank_score >= min_score_to_skip` (0.70) → grade skip (config.yml 라인 247)
- **조건 3:** `max_rerank_score - second_score < min_top_gap_to_skip` (0.05) → short-circuit 방지 (라인 256)
- **수집:**
  ```bash
  # 로그 파싱으로 short-circuit 비율 계산
  grep "\[RAG\] \[RETRIEVE\] 리랭킹 선별 완료" reports/*.log | wc -l
  grep "short.circuit\|grade.*skip\|min_score_to_skip" logs/*.log | wc -l
  ```
- **평가 스크립트:** `eval_quality.py` `--no-llm` 모드에서 generation 호출 횟수로 추정

### 4.8. Cache Hit %
- **벡터 캐시 히트%:**
  - **로그:** `[RAG] [INDEX] 벡터 캐시 히트: {N}개 청크 로드됨` (pipeline_builder.py:229)
  - **수집:** `cache.load()` 성공 여부 → `cache_data and all(x is not None for x in cache_data)`
  - **계산:** `히트수 / (히트수 + 미스수) × 100`
- **쿼리 캐시 히트%:**
  - **로그:** `[RAG] [PREPROCESS] 쿼리 캐시 히트 — generate 단축 경로` (라인 118)
  - **수집:** `is_cached=True`인 쿼리 비율
  - **캐시 키:** `{file_hash}:{query}` (라인 101)
  - **임계값:** `QUERY_CACHE_MIN_CONF` (기본 0.85)
- **임베딩 캐시 히트%:**
  - **수집:** `_get_embeddings()`에서 `cached_vector is not None`인 비율
  - **캐시 키:** `emb:{model_name}:{xxhash}` (라인 330-331)
- **M_unique (고유 임베딩 수):**
  - **정의:** `len(missing_texts)` = 신규 임베딩이 필요한 고유 텍스트 수
  - **수집:** `_get_embeddings()` 내 `missing_texts` 리스트 길이
  - **의미:** 캐시 효율성 = `1 - (M_unique / 총_청크수)`

### 4.9. rerank metadata_hit
- **정의:** 리랭커가 메타데이터 캐시에서 임베딩을 재사용한 비율
- **수집:** `src/core/async_reranker.py:116-163` `_get_doc_embeddings()`
  - Module-level cache hit: `_get_cached_emb(doc.page_content)` 반환 값이 있음
  - Metadata-level cache hit: `doc.metadata.get("embedding_vector")` 존재
- **로그:** 직접 로그 없음 → 코드 내부 카운터로 측정 필요
- **측정 명령:**
  ```python
  # 벤치마크 스크립트에서 카운터
  metadata_hit_count = 0
  total_docs = 0
  for doc in documents:
      total_docs += 1
      if _get_cached_emb(doc.page_content) is not None or doc.metadata.get("embedding_vector"):
          metadata_hit_count += 1
  metadata_hit_rate = metadata_hit_count / total_docs * 100
  ```

### 4.10. hit율 (검색 정확도)
- **P@1:** 첫 번째 결과의 관련성
- **MRR@5:** 상위 5개 결과의 Mean Reciprocal Rank
- **수집:** `eval_quality.py` `--no-llm` 모드 출력
- **golden_set.json:** `tests/data/golden_set.json`의 `required_chunks` 기반 context_recall
- **명령:**
  ```bash
  python scripts/evaluation/eval_quality.py --tag baseline --no-llm --testset_n 3
  # reports/eval_quality_baseline_<ts>.md 에서 P@1, MRR@5 추출
  ```
