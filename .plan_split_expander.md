# Implementation Plan — Split "Answer Details" Expander into References-Only + Process/Metrics Captions

**Status:** AWAITING USER APPROVAL — no code has been changed.
**Scope:** Streamlit UI only (`src/ui/`). Orchestration/RAG core untouched.
**Source:** Hyperplan adversarial discussion (4 sequential agents: explore → critique → cross-attack → refine).

---

## 1. PHASE ORDER

Each phase is an independent, individually reversible unit. Implement strictly in this order.

### Phase 1 — Single Source of Truth for Streaming State (prerequisite)
- **File:** `src/ui/handlers/streaming_state.py` (+ consumers in `src/ui/components/chat.py`).
- Replace ad-hoc accumulation of `_aux_state` (thought, documents, metrics, citations, process_steps) with one typed state object/flag that BOTH the captions and the answers-expander read from.
- **Exit criteria:** renderers read from the same state object; no duplicated dicts between caption path and expander path.

### Phase 2 — Expander: References Only, Collapsed by Default
- **File:** `src/ui/components/chat_references.py` — `render_generation_expander` (~L160; expander L227-258).
- Remove the Process and Metrics tabs from the expander; keep only the References tab.
- Set `expanded=False` on the top-level `st.expander` (collapse by default; user opens intentionally).
- **Exit criteria:** expander shows references only, collapsed by default; no dangling references to removed tabs.

### Phase 3 — Process Caption ABOVE the Streaming Answer
- **File:** `src/ui/components/chat.py` — caption area above the answer (`~L152/L158` interrupted state; `~L166` streaming).
- Render concise per-phase status: `identify → retrieve → generate` (current phase highlighted).
- Must NOT overload: show compact phase chips/one-line status, not full logs. Suppress on non-streaming states.
- **Exit criteria:** process steps visible above the answer during streaming, disappearing/condensing when complete.

### Phase 4 — Metrics Caption BELOW the Streaming Answer
- **File:** `src/ui/components/chat.py` — below-answer caption (`~L166` / `~L223` "Answer complete" area; `_draw_streaming_message` ~L301; `_render_streaming_with_write_stream` ~L467; `aux_ph` ~L490).
- Append metrics (latency, token counts, model name) to the completion caption, read from Phase-1 state only.
- **Exit criteria:** metrics shown under the answer on completion; expander stays references-only.

## 3. RISKS & MITIGATIONS

| # | Risk | Mitigation |
|---|------|-----------|
| 1 | Streaming refresh conflicts (caption rewritten mid-stream) | Phase 1 first; captions render from state object, never write state |
| 2 | Expander collapse hides references context | Default `expanded=False` but keep it above the answer's visual hierarchy; references remain one click away |
| 3 | Caption overload above answer | Per-phase summary text only; no log dumps; suppress during idle |
| 4 | State duplication between caption and expander | Single source of truth (Phase 1); `_aux_state` removed as accumulator |
| 5 | Regression on "Answer complete" flow | Phase 4 leaves the existing string intact and appends metrics — additive change |
